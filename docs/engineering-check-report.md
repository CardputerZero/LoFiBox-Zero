# LoFiBox Engineering Check Report

This report records the current repository posture against the official Debian/Ubuntu archive target.

## Current Status

- Offline build: install-skeleton CMake configure/install passes in the existing local Docker image `lofibox-zero/dev-container:trixie`; full clean-chroot and source-package builds are still not proven.
- Debian package build: `scripts/create-orig-tarball.ps1` plus `scripts/run-dpkg-buildpackage.ps1 -BuildArgs "-us -uc"` now passes with the dedicated local package-build image `lofibox-zero/package-build:trixie`, producing source and binary artifacts including `.dsc`, `.debian.tar.xz`, `.orig.tar.xz`, `.changes`, `.buildinfo`, `.deb`, and dbgsym `.deb`.
- Debian build dependency check: `scripts/check-debian-builddeps.ps1 -Image lofibox-zero/package-build:trixie` passes. The older local dev image still lacks `debhelper-compat (= 13)` by design.
- Package smoke status: installing the generated `.deb` in the package-build image, running `lofibox --help`, `lofibox --version`, `desktop-file-validate`, and `appstreamcli validate --no-net` passes. The Docker image excludes `/usr/share/man/*` at install time, so manpage presence must be checked from package contents in that image.
- Autopkgtest status: `autopkgtest lofibox_0.2.0-1_amd64.changes -- null` passes with `smoke PASS`. The smoke test validates installed binary availability, CLI help/version behavior, desktop metadata, AppStream metadata, and hicolor icon installation. It is intentionally not marked `superficial` so autopkgtest exits successfully as a real package-level gate.
- CI/package validation alignment: `.github/workflows/linux-ci.yml` now runs the same package-level gates after CMake tests: Debian binary package build, `lintian`, and `autopkgtest`. Local validation is represented by `scripts/run-debian-package-validation.ps1`, which orchestrates orig tarball creation, package build, lintian, and autopkgtest using the dedicated local package-build image. Routine local lintian/autopkgtest runs use Docker `--network none`; the package-build image must carry the needed apt indexes instead of redownloading them every validation pass.
- Lintian status: only `initial-upload-closes-no-bugs` remains, which is expected until an ITP/release bug number exists. The package-build script now copies the source tree into a normalized-permission Linux workspace before building, avoiding Windows bind-mount executable-bit pollution in source packages.
- Compile warning governance: project-owned warnings must be fixed at source; third-party implementation warnings may only be suppressed at the narrow include site and must be documented in `docs/third-party.md`.
- SPDX governance: project-owned C/C++, CMake, scripts, CI files, documentation, man pages, desktop metadata, AppStream metadata, MIME metadata, and SVG files now carry SPDX headers. `scripts/check-spdx.ps1` is wired into CI as the repository-level header gate.
- Architecture boundary governance: `scripts/check-architecture-boundaries.ps1` is wired into CI to prevent UI/page code from including `src/app`, concrete platform, or backend layers; prevent UI/page code from referencing `app::` internal types; prevent `core` from depending upward; and prevent host/device adapters from depending on concrete app/page implementations.
- UI/input/command/page-model/lifecycle ownership status: page renderers, shared UI primitives, topbar/list/help chrome, and UI projection structs now live under `src/ui`; page-level input routing lives in `src/app/app_input_router.*`; page command execution semantics live in `src/app/app_command_executor.*`; page titles/rows/list classification live in `src/app/app_page_model.*`; page-level render routing and UI view assembly live in `src/app/app_renderer.*`; app tick ordering lives in `src/app/app_lifecycle.*`; scalar/session runtime state lives in `src/app/app_runtime_state.*`; library/playback controller ownership lives in `src/app/app_controller_set.*`; `src/app/app_runtime_context.*` adapts those objects to narrow target interfaces; `LoFiBoxApp` is a thin public facade.
- God-object decomposition status: playback enrichment worker lifecycle now lives in `src/app/playback_enrichment_coordinator.*`; runtime enrichment protocol clients are split into AcoustID, MusicBrainz, Cover Art Archive, LRCLIB/lyrics.ovh, and ffprobe client files; lyrics cache/writeback policy lives in `src/platform/host/lyrics_pipeline_components.*`; library queries, list projection, open-action resolution, and list context are split into dedicated app components; app-to-UI projections live in `src/app/app_projection_builder.*`; lyrics-page layout/effect algorithms live in `src/ui/widgets` and `src/ui/effects`; host runtime helper families are named in `src/platform/host/runtime_host_tools.*`.
- Integrated product core status: `docs/specification/integrated-product-core-spec.md` now defines the shared responsibility model across media identity, media source, media stream, playback facts, audio pipeline, enrichment pipeline, library facts, UI projection, and runtime shell adapters. Future playback, remote, metadata, library, UI, and desktop work must align to that model rather than landing as local feature patches.
- Playback/audio lifecycle status: playback time advancement, backend command sequencing, completion policy, and visualization-frame sourcing are split from `PlaybackController` into dedicated integrated-core playback components. `PlaybackController` now delegates runtime ticking and backend transitions through a coordinator and no longer polls backend state or computes finish policy inline.
- Identity/enrichment/library fact status: enrichment metadata application now goes through a merge policy that fills placeholders without overwriting existing non-placeholder title/artist facts; lyrics writeback policy is guarded by match confidence; play count and last-played mutations are moved behind a library mutation service.
- Remote/security foundation status: Jellyfin, OpenSubsonic, Navidrome, and Emby are now registered as first-batch supported remote source families, with Navidrome explicitly governed as OpenSubsonic-compatible. Remote source profiles now carry credential references and secure TLS defaults, while secret redaction helpers provide a shared boundary for log-safe source diagnostics.
- Projection/settings/desktop boundary status: Settings row assembly and Source Manager row assembly now live in app projection builders, while desktop command and now-playing projection boundaries exist under `src/desktop`. This keeps Settings, source/server management, and future MPRIS/media-key adapters consuming app projections instead of UI pages or backend/provider internals.
- Runtime service registry status: `src/app/runtime_services.*` groups injected capabilities into connectivity, metadata, playback, and remote service groups; architecture checks reject legacy flat provider access from `RuntimeServices`.
- Runtime capability boundary status: host runtime service construction is split into service group providers, metadata online lookup ordering is delegated to a dedicated orchestrator, library fact storage is behind `LibraryRepository`, and playback runtime uses an `AudioPipelineController` facade for backend state and visualization frames. Smoke tests now cover these new boundaries so future feature work cannot silently collapse them back into app-level god objects.
- Phase 3+4 product-domain status: remote provider contracts now declare provider family and capabilities; remote server profiles persist through an XDG profile store without writing secrets; Source Manager rows are projected from provider manifests and persisted profiles; unified `MediaItem`, local/remote search mapping, and mixed queue models exist; library indexing and durable-store responsibilities are split into `LibraryIndexer` and `LibraryStore`; enrichment authority policy gates metadata/artwork/lyrics trust and lyrics writeback; DSP chain models EQ, ReplayGain, limiter, and the audio pipeline facade consumes DSP profiles; desktop integration now exposes app-side MPRIS and notification projections without taking a dependency on UI pages or playback backends.
- Phase 5 implementation-placement status: playback implementation files now live under `src/playback`; audio decoder/output boundaries live under `src/audio/decoder` and `src/audio/output`; the host audio output implementation lives under `src/audio/output`; playlist and plugin manifest boundaries live under `src/playlist` and `src/plugins`; empty `src` placeholder directories and `.gitkeep` markers have been removed. `scripts/check-implementation-placement.ps1` is wired into CI so future work cannot reintroduce aspirational module directories or hidden implementation placement.
- Phase 5 remote-provider status: Jellyfin, OpenSubsonic/Navidrome-compatible, Navidrome-compatible, and Emby provider paths now expose real probe, search, recent/latest, library-track catalog enumeration, and stream resolution through `RemoteMediaServices`. Provider protocol behavior lives under `src/remote/jellyfin`, `src/remote/opensubsonic`, `src/remote/navidrome`, and `src/remote/emby`; `scripts/remote_media_tool.py` is only the private helper entrypoint. Emby catalog lookup prefers `Audio` items and falls back to media items resolvable through Emby's audio-stream endpoint when a real server has an empty music catalog. `lofibox_remote_media_smoke` validates the protocol paths against an isolated mock server. `lofibox_real_emby_integration_smoke` is an optional real-server gate that reads Emby URL, username, and password from environment variables only, skips when unset, and verifies authenticated probe, catalog enumeration, and stream URL resolution without committing or persisting credentials. A 2026-04-27 local run against the available LAN Emby server passed.
- Cache/offline status: unified cache ownership now exists under `src/cache/cache_manager.*` and is exposed through `RuntimeServices.cache`. It covers playback buffer, recent browse, artwork, metadata, lyrics, remote directory catalogs, station lists, and offline audio buckets; each bucket has capacity and age policy, remote-directory and station-list persistence helpers, recent-browse history, offline track save/lookup, album/playlist sync planning, usage reporting, and garbage collection. Host runtime construction binds this manager to the XDG cache directory.
- DSP/EQ status: the DSP domain now owns final-form EQ profile semantics rather than only page sliders. Built-in presets, user preset CRUD/import/export, device/content bindings, 10-band graphic EQ, parametric bands, high-pass/low-pass filters, balance, loudness, limiter, ReplayGain mode, bypass, preamp, and smoothing helpers live under `src/audio/dsp/dsp_chain.*`. `AudioPipelineController` continues to consume the shared `DspChainProfile`, keeping DSP as a processing-chain concern instead of a page-local setting.
- Streaming completion status: the remote domain now declares provider families for direct URLs, internet radio, playlist manifests, HLS, DASH, SMB, NFS, WebDAV, FTP, SFTP, and DLNA/UPnP in addition to Jellyfin/OpenSubsonic/Navidrome/Emby. Remote catalog hierarchy, stream-source classification, buffer/retry/reconnect/prefetch/quality policy, and stream diagnostics are represented by compiled models and smoke tests.
- Library/metadata/playback stability status: library governance now covers incremental changes, migration planning, smart playlists, source-grouped search explanations, and duplicate recording decisions. Metadata governance now covers fingerprint index entries, conflict reporting, artwork provenance priority, and writeback format coverage. Playback stability now covers start/end jitter suppression plus gapless/crossfade preparation policy.
- Desktop/security/UI completion status: desktop runtime integration now has explicit MPRIS/D-Bus/media-key/notification/open-request state. Credential governance now has a keyring-facing store abstraction, lifecycle status, revocation, and read/write permission labels. Final product surface pages for Search, Queue/Up Next, Remote Browse, Server Diagnostics, Stream Detail, and Playlist Editor are now present in page-model form with tests.
- Vendored dependency status: `src/third_party/stb_image.h` is registered as `MIT OR Unlicense`; it still needs a keep-vendored versus system-package decision.
- Copyright status: initial license policy is established: code/docs `GPL-3.0-or-later`, metadata `CC0-1.0`, project-created installable visual assets `GPL-3.0-or-later`, generated fixtures `CC0-1.0`, third-party material by original license.
- PNG resource status: upstream author confirmed all PNG resources in this repository are self-created and not downloaded from third-party sources.
- Design prototype status: `assets/design` has been removed from the repository because prototype images are not runtime assets and should not be packaged.
- XDG path compliance: a host runtime path boundary now exists for config, data, cache, state, runtime, and temporary paths. Runtime cache, runtime logs, script payloads, and single-instance locks use that boundary; `lofibox_xdg_paths_smoke` validates Linux XDG environment handling.
- Runtime helper compliance: Python helper scripts are installed into the private application directory and resolved in the order `LOFIBOX_HELPER_DIR`, installed private helper directory, then source-tree `scripts/` fallback. `tag_writer.py` depends on `python3` and `python3-mutagen`, both declared in `debian/control`; `remote_media_tool.py` currently uses only Python standard-library modules. Autopkgtest verifies installed helper files and Mutagen availability, while `lofibox_helper_script_path_smoke` validates explicit override behavior.
- Host optional fingerprint provisioning condition: `scripts/ensure-host-fpcalc.ps1` provides a direct host check/install path for Chromaprint/fpcalc. On 2026-04-27, the current Windows host was provisioned with `fpcalc` 1.6.0 through winget after non-elevated Chocolatey installation failed on locked `C:\ProgramData\chocolatey` state.
- Direct Linux desktop-widget condition: the real X11 target is configured by `linux-x11-debug` and built by `linux-x11-debug-build`; SDL or mock desktop simulators remain intentionally outside the product architecture.
- Debian source package condition: initial `debian/` skeleton exists and local `3.0 (quilt)` source-package build passes using a generated `lofibox_0.2.0.orig.tar.xz`; real upload readiness still needs an upstream release tag and maintainer/release metadata.
- Desktop integration condition: `.desktop`, AppStream, hicolor icon, and MIME package files exist and validate in WSL; MPRIS, D-Bus, media keys, and notifications remain implementation work.
- Test isolation condition: specified as required; implementation must ensure no dependency on real user music, external internet, real audio devices, or polluted `HOME`.

## Engineer Decision Points

- Exact copyright holder naming policy for future organization or maintainer transfer.
- GUI toolkit or rendering backend policy for the Linux desktop target.
- Whether providers are internally compiled first or exposed as binary plugins with a C ABI.
- Exact Debian maintainer identity, homepage, VCS URLs, and release tag policy.
- Which dependencies are mandatory, optional, `Recommends`, or provider-package-specific.
- Whether the existing local Docker image should be rebuilt to include `desktop-file-utils` and `appstream`, or whether metadata validation should remain a WSL/CI-only check until the image is refreshed.
- A dedicated local package-build image definition now exists at `docker/package-build.Dockerfile`; it derives from `lofibox-zero/dev-container:trixie` and keeps Debian package tooling separate from runtime and device images.
- Font policy is now system-font based; keep `fonts-noto-cjk` as Debian packaging recommendation and do not reintroduce vendored CJK font binaries without a new copyright review.

## Immediate Governance Result

The current specification baseline now treats Debian/Ubuntu official archive readiness as a hard engineering constraint and feature completeness as a hard product constraint.
Future implementation must organize complexity through architecture, dependencies, providers, tests, and packaging rather than deleting capability domains.

## 2026-04-27 Functional Completion Pass

The latest implementation pass moved several previously model-only areas into application behavior:

- Remote profiles are no longer only listed: selecting one probes it, opens Remote Browse, resolves playable catalog entries, exposes Stream Detail diagnostics, and starts remote playback via `AudioPlaybackBackend::playUri`.
- Host remote provider tooling now supports `browse` for Jellyfin, Emby, OpenSubsonic, and Navidrome-compatible servers, in addition to probe/search/recent/library/resolve.
- Configured direct URL, radio, adaptive stream, playlist manifest, LAN-share URL, and DLNA/UPnP URL sources are handled by the host remote runtime without going through protocol-specific Python clients.
- CLI positional file/URL opens are represented as desktop open handoff into the same local/remote playback model, not as a separate target-only code path.
- Search, Queue/Up Next, Remote Browse, Server Diagnostics, Stream Detail, and Playlist Editor are now navigable/actionable small-screen pages, not only enum entries.
- Library governance and playback stability policies are now called by runtime paths. Metadata governance gained persistent fingerprint-index storage.

Validation added/kept:

- `lofibox_remote_browse_playback_flow_smoke` verifies remote profile selection through actual remote URI playback.
- `ctest` currently covers 51 smoke tests across app, remote, library, metadata, cache, DSP, desktop/security, playback, and packaging-facing helpers.

Host deployment note: `XdgRemoteProfileStore` now supports a user-state credential companion file at `~/.local/state/lofibox/remote-credentials.tsv`. This keeps source profiles free of raw secrets while allowing deployed devices without Secret Service/libsecret wiring to authenticate configured media servers.
